# 其余编码思维条目

一条一句，写代码时对着过。都是参考角度，不是规定。

- **命名先于结构。** 名字定不下来，通常是职责没分清；先把这件事叫什么想清楚，结构自然出来。
- **一层抽象一幕戏。** 同一个函数里既处理协议细节又处理业务规则，就是混层；调用下层时不要伸手拆开下层的数据结构。
- **状态尽量少。** 能算出来的不存，能传参的不放全局，能在局部用完的不设成员变量。
- **副作用收敛。** 改状态的代码集中一处，读写不混在同一个函数里；集中之后测试与排查都省事。
- **错误不许吞。** 可预期的失败显式返回并说明原因，不可预期的抛出去；不要 `catch` 之后什么都不做。
- **边界先行。** 动手前先想空值、0、负值、超长、并发同时进来会怎样，这些通常在提交后才被发现。
- **依赖方向。** 业务代码不依赖框架细节，换框架时只改接入那一层；数据库、消息、第三方调用都收到一个边界后面。
- **可测性。** 写完能说出怎么验；说不出来，说明边界没收干净，或者依赖没隔开。
- **重复第三次再抽。** 第二次先照抄，第三次动手泛化；两次还看不出稳定的形态。
- **注释不替设计。** 需要大段注释解释它在干什么，先想能不能拆开；注释讲"为什么"就够，见 `comment-trimming` 插件。
- **改动可回退。** 一次改动只做一件事，便于出问题时单独撤销；顺手改的、重构的、加功能的分开做事。
- **先看调用方再改签名。** 改公共函数的入参或返回值前，先列出所有调用方，逐个确认。
