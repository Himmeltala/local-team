# 输出侧省 token

省的是 AI 写出去的内容，不是把证据删掉。用户输入侧的节省另有 `input-guard` 插件负责。

## 结论先行

- 第一句给判断或结果，背景与过程放后面。
- 用户在等答案时，不要先复述需求、先声明"我将要做什么"。
- 多步操作完成后，先报结果，再列关键步骤。

## 不复述

- 不回显用户的问题。
- 不重复上一轮已经确认的结论。
- 不把文件内容整段抄回，引用位置即可。
- 不重复贴已经贴过的日志与报错。

## 只给相关片段

- 代码改动：给改动前后的关键几行，上下文用函数名、行号定位。
- 日志：给报错及其前后几行，其余说明省略范围。
- SQL：给出问题的查询与关键条件，长字段列表可省。
- 配置：只给修改的键，不整份配置回显。

## 结构从简

- 能用一句话说清的，不用三行列表。
- 列表只在确有并列项时用，每条不超过一句。
- 不为了显得完整而保留空小节；没有内容就不写。
- 表格只在多维对照时用，单列信息不用表格。

## 分轮输出

- 大任务先给结论、影响范围与下一步，细节等用户要再展开。
- 探查类任务先报找到什么，不逐条播报搜索过程。
- 长回复若超过一屏，考虑拆成"结论"与"依据"两轮。

## 什么不能省

- 结论依赖的证据：SQL、日志关键行、文件与行号。
- 风险与未验证项：没跑测试、没复现、影响范围不明，必须写明。
- 用户明确要求展开的部分。
- 安全提醒与不可逆操作确认。
