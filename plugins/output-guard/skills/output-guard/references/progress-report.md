# 进度与结果汇报模板

## 结构

```
已完成：<有可核对结果的事项>
未完成或受阻：<没做完的，卡在哪里，需要什么>
下一步：<接下来要做的动作>
```

## 写法

- **已完成**写结果，不写投入的时间与过程；有产物就给路径或命令输出摘要。
- **未完成或受阻**写阻塞点与需要谁配合；没有阻塞就省略这一节。
- **下一步**一条一个动作，按优先级排；不确定方向时先写要确认的问题。

## 伸缩

- 事情少时三节并成两段：一段写完成情况，一段写下一步。
- 全部完成时省略"未完成或受阻"，直接写结果与后续建议。
- 全部未开始时只写"下一步"与依赖条件，不要用"进行中"含糊带过。

## 示例

```
已完成：排查结论已给出，根因定位到服务层空区域判断；修复方案已与用户确认。
未完成或受阻：修复代码未提交，等用户确认是否顺带清理同文件注释。
下一步：改代码并自测，再按提交规范写一行提交信息。
```
