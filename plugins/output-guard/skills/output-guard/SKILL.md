# AI 输出规范

命中场景时套用对应模板；没命中按普通回复，但输出侧的省 token 规则始终适用。

## 选哪个模板

| 场景 | 常见说法 | 模板 |
|---|---|---|
| 排查与故障结论 | 排查完了、根因是什么、为什么出错、问题出在哪 | `references/troubleshooting-reply.md` |
| 代码改动说明 | 改了什么、改动说明、影响范围、怎么验证 | `references/change-summary.md` |
| 进度与结果汇报 | 进度、汇报一下、做到哪了、结果怎么样 | `references/progress-report.md` |

用户显式点名某个模板时，按点名的来。

## 套用规则

- 小节顺序固定；内容少时合并或省略小节，不写"无"占位。
- 每节一到三条，一条说一件事。长解释放在小节之外，不塞进条目。
- 只写有依据的内容。没查到的、没验证的写明"未确认"或"未执行"，不要编。
- 模板只管结构，措辞按 `chinese-writing` 插件的规范。

## 输出侧省 token

- 结论先行：第一句给结果或判断，过程放在后面，不要先铺背景。
- 不复述用户的问题，不重复上一轮已经说过的话。
- 不整段粘贴文件、日志、表结构；只引相关行，位置写到文件与行号。
- 代码只给改动片段，上下文用函数名或行号表示；不重发未改动的部分。
- 列表与表格只在确实有并列项时用；一条一句话也能说完的，不用表格。
- 长任务分轮输出，先给结论与下一步，细节等用户要再展开。

细则见 `references/token-saving.md`。

## 边界

- 只管 AI 的回复侧；用户输入侧的敏感信息与冗余，归 `input-guard` 插件。
- 中文措辞与篇幅数值，以 `chinese-writing` 插件为准。
- 排查本身怎么查，走 `bug-tracing` 技能；本技能只负责结论怎么组织。
- 省 token 不等于省略证据。结论依赖的 SQL、日志行、代码位置必须给全。
