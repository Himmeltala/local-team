# 注释里的特殊符号：禁的是这些

团队前端项目靠仓库内的自定义 eslint 插件强制。以下是规则 `illegal-annotation` 的实际行为，来自逐行读规则源码，并实跑正则验证。不要照抄插件自带 README 的描述——那份说明与实现不一致，已核对出两处。新项目若带了同名的本地规则，先读它的源码确认行为再照做。

规则扫所有注释，命中报 error 并可自动修复。它的 `SYMBOL_RE` 实际覆盖：

- ASCII 加号 `+`
- 乘号 `×`
- 箭头区 `←` 到 `⇿`（含 `→`）
- 制表与线条 `─` 到 `╿`
- 几何图形 `■` 到 `◿`
- 装饰符号 `☀` 到 `➿`（含 `★` `✓` `✗`）
- emoji（各 surrogate 区段）

这份清单对 Java 与 mapper XML 的注释同样适用：SQL 的 `--` 注释、结构层的 `<!-- -->` 注释，禁止的符号一个不少。范围只限注释——SQL 语句本身、字符串常量、注解值里的符号是数据，一个字不动。前端由 eslint 自动拦，Java 与 mapper 没有自动拦截，写完自己看一眼。

**不在禁止范围**：`=` 和 `>`，所以 `=>` 不会被拦；`-` `*` `/` 也不禁。

两个真实的坑，别被规则自己的说明带偏：

- 加号 `+` 被禁，但规则自带测试文件里写着"数学符号 `+ - * /` 不在禁止范围"，与实现矛盾。以 `SYMBOL_RE` 为准——写 `// 宽×高`、`// CRUD + 标记已读` 会被 `--fix` 静默删掉符号。
- 规则里用了 `/g` 正则加 `.test()` 遍历注释，`lastIndex` 会跨注释残留，导致违规可能被漏报。别指望它兜住全部，写完注释自己看一眼。
