注释约定（comment-trimming 插件，全程适用）：

- 注释稀疏优先：默认可不写。注释不复述代码，只讲"为什么"，且只讲本段代码自身：不写调用关系与调用链（谁调用我、我调用谁、上游何时写入、下游谁消费），那类信息看查找引用。禁 emoji、`====` 分割线、★✓ 这类装饰；符号与箭头规则以 chinese-writing 插件为准，注释里也不许用。横幅注释只剥装饰、留住句子。
- 注释要短：篇幅以 chinese-writing 的篇幅标准为准（一行，最多两行），行内、字段与方法注解、类头 `说明：`、XML 与 SQL 注释都一样；一行写不完的信息挪进命名或文档，不要写成一段。承载业务口径的长注释也照压，压不动的报告给用户；Vue 文件头块与功能性指令除外。
- 本次编辑碰到的文件，顺手把该文件里的乱注释整文件清干净；没编辑过的文件不碰。清理动到本次改动之外时，在提交信息那一行里带上"顺带清理注释"。功能性指令（eslint-disable、@SuppressWarnings、noinspection）和 TODO / FIXME 永远不删。
- Java 字段用 @ApiModelProperty、控制层方法用 @ApiOperation 表达，不要改成 Javadoc；Service 方法与私有方法不加注解。Vue / JS 文件头注释块由 eslint 强制，必须保留。详见 comment-trimming 技能。
