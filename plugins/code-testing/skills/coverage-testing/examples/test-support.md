# 测试基建三件套

抽成一个 `XxxTestSupport` 类放进测试包，所有用例共用。抽之前先看项目里有没有，有了就用现成的，别各写一遍。

Java 的可照抄骨架在 `skills/java-testing/examples/ForwardTestSupport.java`；下面只写三件套各自要满足什么，换语言照这些要求实现即可。

## 一、轮询等待

一切"等某件事发生"的地方都走它，不要 `Thread.sleep(500)`。要满足：

- 签名是 `await(说明, 条件, 超时)`，条件用布尔表达式，超时可选、有默认值。
- 默认超时给足（8 秒量级）：慢机器上不假红，真卡死也还能在可接受时间内暴露。
- 轮询间隔 20 到 50 毫秒。太密费 CPU，太疏拖时间。
- 超时抛断言失败，并且**把说明带上**，失败时不用回看代码。
- 被中断要往外抛，不能吞掉——吞掉会让"测试卡住"变成"超时后仍继续跑"。

## 二、造数函数

- 内容可预测：按位置生成字节，别用全零数组——少了一段看不出来。
- 大小可参数化：边界值用例要用（空、刚好等于上限、超一点）。
- 不同用例造出来的东西不重样：按类型或序号把内容区分开，断言时能看出是不是张冠李戴。

典型的两支：造一条协议报文（头部带类型，包身按位置填），造一段指定大小的载荷（大报文用例用）。

## 三、目录与文件断言

轮询条件里要反复查目录，抽成小函数，避免每个用例重复写 `listFiles` 加过滤。要满足：

- 列指定后缀的文件，返回列表。
- **目录不存在时返回空列表**，不要返回 null——省得每条用例判一次。
- 按文件名排序，让顺序断言稳定。

常见做法是再包一层语义化的入口，比如 `failedFiles(cacheDir)`、`succeededFiles(cacheDir)`，用例里读起来就是"失败目录里的文件"。

## 命名与断言消息

- 测试方法名直接写断言的行为，用母语写：`推送成功后报文原样到达第三方并迁入成功目录`。失败时名字本身就是说明。
- 每条断言都带消息，尤其"目录为空""不应归档"这类否定断言——否则失败时只知道不成立，不知道为什么。
- 一个方法一条断言主线。要断言的东西多了就拆，别写成二十行的巨型用例。
