# 把链路用测试锁住，再把覆盖率补上去

用户调用时带了参数：`$ARGUMENTS`

- 参数是模块或链路：从第 1 步走。
- 参数是覆盖率目标：走第 3 步与第 4 步。
- 无参数：先问清测哪个模块、覆盖率目标多少、判据是什么，再动手。

## 与 mock-testing 的分界

| | mock-testing | 本技能 |
|---|---|---|
| 假对端在哪 | 独立进程，起一个模拟服务 | 测试代码里，与被测组件同进程 |
| 谁在跑 | 手工或脚本驱动，跑真链路 | 测试框架驱动，可重复、可回归 |
| 产物 | 验证结论与观察日志 | 能长期留在仓库里的测试用例 |
| 什么时候用 | 对端不可达、只想手工验一遍 | 组件齐了，要把行为锁住防回归 |

两者不冲突：手工用模拟服务摸清链路形状之后，再用本技能把它固化成用例。

## 五步法

1. **定靶子。** 先写清这次要锁住什么行为，一句话一条，别写成"给这个模块加测试"。靶子分三层：正常路径、失败路径、边界值。失败路径包括对端不在、对端断开、对端不读、写超时，边界值包括空、超限、超期。每条靶子对应一个测试方法，名字直接写靶子本身。
2. **搭假对端。** 最外层那个不可控的对端换成进程内假货：真开一个监听端口，被测组件连过来，假对端把收到的字节累积下来供断言。假对端至少要能记连接次数、能主动断开、能只连不读。写法与五个必备能力见 `references/fake-peer.md`。
3. **串真实链路。** 除最外层对端之外，中间组件全用真货：真的事件发布器、真的过滤器、真的缓存与线程池。只 new 出组件、手工注入依赖，不拉 Spring 上下文——上下文一起来就要数据库、要配置中心，测试会脆。这一层跑通才是"链路测通"，把中间件也 mock 掉就只剩单元测试了。
4. **量覆盖补测。** 先跑一遍拿基线，再按未覆盖行逐条补。能造出来的场景补用例；环境故障类分支（磁盘满、权限不可读）记账不补，别为凑数改权限——跑在 root 下会假绿。未覆盖清单怎么分类、怎么记账见 `references/coverage.md`。怎么量、报告为空怎么办，见 `java-testing` 技能的 `references/surefire-and-jacoco.md`。
5. **连跑验稳。** 单次全绿不算数，连跑三轮。偶发失败的三类根因与排查办法见 `references/stability.md`。

## 三条硬规矩

1. **断言落在对端真正收到之后。** "已归档""已置成功"只代表本机写完了。判据与改法见 `references/stability.md` 的根因一。
2. **等待一律轮询，不 sleep。** 固定 sleep 要么不够要么白等，统一走 `await(说明, 条件, 超时)`。
3. **测试当探针，不是当装饰。** 补测时若发现代码行为与配置语义不符，先写成用例把现状钉住，再决定修还是记为已知。测试跑出来的缺陷按产品缺陷报，别在测试里绕过。

## 常见坑

断言在事件完成之前下（最常见）、测试间共享静态状态、临时目录不隔离导致上一条用例的残留被读到、非 daemon 线程池不关闭让 JVM 不退出、覆盖率统计把整个工程算进来导致分母虚高、为覆盖率写只调用不断言的假测试。
