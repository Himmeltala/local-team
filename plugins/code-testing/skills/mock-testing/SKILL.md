# 拿模拟服务把链路跑通

用户调用时带了参数：`$ARGUMENTS`

- 参数是链路、接口或边界：从第 1 步走。
- 参数是故障场景：走第 3 步的故障开关，配合第 5 步逐档验证。
- 无参数：先问清要测哪条链路、判据是什么，再动手。

## 什么时候用

对端在本机起不来（缺硬件、缺依赖、缺环境）、对端不可达、对端还没实现、只想验中间段、要复现线上问题或造依赖数据、要验超时与时间相关行为。

反例：各段本机都能真跑时直接跑真的。模拟服务会把真实问题盖住。

## 边界类型

被测方往外跨的每一处都是边界，都能做模拟：

| 边界 | 模拟的形态 |
|---|---|
| HTTP 与 WebSocket | 本地 HTTP 服务、被动观察器 |
| gRPC 与其它 RPC | 本地假服务，按接口定义实现 |
| 消息队列 | 假 broker、本地主题收发脚本 |
| 数据库与缓存 | 本地库、内存库、只读副本 |
| 文件与对象存储 | 临时目录、本地目录对拷 |
| 串口、设备与硬件 | 假设备脚本、回环 |
| 时钟与随机源 | 可注入的时间源、固定种子 |

模板只有前两类的骨架（`examples/`），其余照同一套路写：抄契约、只做被测方会调到的分支、故障做成开关。

## 六步法

1. **划边界。** 把链路拆成段，逐段问"本机能不能真跑"：产物齐不齐、依赖装没装、硬件在不在、外部服务可达不可达。只有答否的段才做模拟服务，判断结果写成一句话清单给用户过目；能真跑的段越真实越好。
2. **抄契约。** 从被替换方与调用方的源码里抄，不要凭空编：路径或主题、入参与返回的字段形状、成功与失败两种形状、状态推进与去重规则。清单模板与各边界的差异见 `references/method.md`。
3. **写模拟服务。** 优先用平台自带的东西，别为起模拟服务再装依赖；只实现被测方会调到的分支，其余兜底拒绝并写明"模拟服务未实现"（缺了这句会把"模拟服务没实现"误判成"链路断了"）；故障做成命令行开关，成功、失败、参数非法、挂起各一档，不要临时改代码；收到与返回各打一行日志；模拟服务要能改状态，便于构造边界值。模板见 `examples/http_stub.py` 与 `examples/cloud_stub.py`。
4. **接管。** 按影响面从小到大选：脚本自己的参数、应用启动参数、开发代理 target、应用配置文件。改文件前记录原值，收尾还原；共享盘与生产配置不就地改，用只读副本加参数指向。细节见 `references/method.md`。
5. **验证三层。** 模拟服务活着（端口在听、日志打出这次请求）、被测端认账（关键字与顺序符合预期）、落地产物正确（文件、接口状态、库字段、广播消息）。无日志的分支临时加打印，测完删掉；界面不方便看时写被动观察器，见 `examples/ws_probe.py`。
6. **收尾还原。** 停模拟服务、还原配置、核对共享文件、删掉临时打印、把预期噪音写进结论。清单见 `references/verify-and-pitfalls.md`。

## 三条硬规矩

1. **契约从源码抄**，失败分支与成功分支同等对待。
2. **模拟服务只补缺口**，本机能真跑的段不许用模拟服务替。
3. **不碰共享与生产文件**，改用副本加参数指向。

## 常见坑

端口占用、就绪探测只看端口有没有人听、静默失败、单连接服务互相顶替、对端按序号去重、管道提前退出导致误判、产物比源码旧、系统代理拦掉本机请求。开工前把 `references/verify-and-pitfalls.md` 的踩坑清单过一遍，能省一轮返工。
