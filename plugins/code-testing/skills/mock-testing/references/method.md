# 抄契约与接管

模拟服务能不能用，取决于契约抄得准不准。抄错一个字段名或漏一个失败形状，它返回成功、被测方当成通过，链路根本没验到，而且错得很安静。

## 从哪里抄

1. **被替换方的实现源码。** 最准：怎么解析、怎么校验、失败返回什么字段，一看便知。
2. **调用方的源码。** 看它发什么、读返回的哪个字段、按什么判成功（HTTP 常看状态码，业务包常看包体里的业务码），模拟服务按调用方的判据满足。
3. **抓到的真实报文。** 链路曾跑通过的话，抓包、日志、消息存档里的原文最省事，直接照抄形状。
4. **接口文档。** 只能当线索：文档与实现不一致是常态，以源码与实抓为准，差异记进结论。

## 契约清单模板

每个被模拟的边界逐条填，填不出就是还没抄清：

```
边界与方向：HTTP 出站 / 消息消费 / 库表写入 …
地址或主题：
入参：字段名、类型、格式（小数位、字符串还是数字、是否二次编码）、可空性
成功形状：状态码或确认方式 + 一条真实例子（原样抄）
失败形状：各失败类型的码、字段名与形状
状态推进与去重：按什么去重、重复请求会怎样
副作用：对端收到后会不会回推、写库、改状态
```

成功形状与失败形状都要抄。只做成功分支的模拟服务，一遇异常路径就没得测。

## 按边界的契约差异

| 边界 | 要多抄的 |
|---|---|
| HTTP 与 WebSocket | 尾斜杠是否敏感、鉴权头、Content-Type、成功判据是状态码还是业务码 |
| gRPC 与其它 RPC | 接口定义、错误码与详情字段、超时与重试语义 |
| 消息队列 | 主题与分区、确认与重投语义、消息头、顺序保证 |
| 数据库与缓存 | 表结构与约束、事务边界、默认值与精度、超时 |
| 文件与对象存储 | 路径规则、编码、换行、权限、覆盖还是追加 |
| 串口与设备 | 帧格式、字节序、心跳与超时、重连行为 |
| 时钟与随机源 | 推进方式、时区、单调性、种子能否固定 |

## 检查点

- **路径规范化。** 带不带尾斜杠在很多实现里是同一路由，有的框架却会 301 或 404，抄的时候两边都试。
- **字段类型与格式。** `"12.3"` 与 `12.3` 不等价，`"12.345"` 与 `"12.3"` 也不等价，小数位照抄。字段本身是序列化字符串的（常见于"负载"这类字段）要确认是对象还是字符串。
- **枚举、时间与序号。** 取值从枚举类或常量确认，别按字面猜；序号常带隐含规则，例如前缀是年份、用于分表，格式错了对端直接不认。
- **错误码字段名。** `code`、`status`、`errcode` 各家不同，取错字段会让失败分支永远不生效。
- **鉴权与校验。** 模拟服务要不要验 token 或签名，取决于被测方是否真的会带、真的会验；别替被测方绕过校验，那等于没测。
- **状态推进、去重与超时。** 真实服务不是纯函数：重复请求会被去重、限流、按序号落库，对端不可达还有重试次数与间隔；模拟服务里显式决定要不要复刻，并写进结论。

抄完自检：拿一份真实成功记录逐字段比对模拟服务的返回，失败记录同做一遍；每个失败分支都能触发一次；不确定的地方标注出来告诉用户。

## 接管：把被测端的地址指到模拟服务上

模拟服务起好了，被测端仍然打到真地址，这轮测试就是白跑。手段按影响面从小到大：

1. **脚本自己的命令行参数。** 给模拟服务或造数脚本加 `--target`、`--backend` 一类参数，默认指向真地址，测试时显式传模拟服务的地址。
2. **应用的启动参数。** 不改文件，只在启动命令上加覆盖项（Spring 形如 `--rootPath.cachePath=/tmp/xxx`），命令行优先级高于配置文件。启动命令要落进起停脚本，别只留在终端历史里。
3. **开发代理的 target。** 改 `vite.config.js` 一类配置时注意：rewrite 会剥掉路径前缀，模拟服务的路由按剥完之后的路径写；`changeOrigin` 会改 Host 头；同名前缀可能还有别的规则，改前把整段读完。
4. **应用配置文件。** 影响面最大，优先级最低，改之前先问前三种为什么不行。共享盘与生产配置一律不就地改：复制到临时目录，只改副本里那一两个键，再用启动参数指向副本。

**地址决策链。** 有些程序按优先级链取地址：先读运行时配置，读不到才回退启动参数或默认值，只改一处可能不生效。从代码里找解析地址的类或函数看取值顺序，起模拟服务后用它的请求日志反证：日志里有请求，说明接管生效；一条没收到，说明流量走了别处。

**改动记录表。** 每改一处记一行，收尾照着还原：

```
文件或参数：<路径或参数名>    原值：<改之前的值>
新值：<模拟服务的地址或副本路径>    生效方式：<重启 / 重跑构建 / 热更新>
```

**还原。** 配置文件类改动用版本控制还原（`svn revert` / `git checkout --`），比手工改回去可靠；启动参数类确认脚本里没留测试用的覆盖项；共享文件用 md5 核对并把结果写进结论；有意长期保留的代理改动也要写明，别让下一个人以为是漏改。
