# 敏感信息清单与处理

## 高敏感，默认不建议发

- 私钥、证书私钥部分、签名密钥
- 访问令牌、刷新令牌、会话 Cookie
- 数据库连接串中的账号与密码
- 云服务 AccessKey、SecretKey
- 生产环境管理员账号与密码

处理：不复制原值；提醒用户在对应平台轮换；需要排查时用环境变量名或配置项名代替。

## 个人信息，发之前脱敏

- 身份证号：保留前六位与后四位，或只写位数
- 手机号：保留前三后四
- 银行卡号：只留后四位
- 姓名与地址：换成"某先生""某小区"这类占位
- 证件、人脸、保单影像：只给路径与用途，不发内容

判断标准：这组信息能不能定位到具体某个人。能，就脱敏。

## 内部信息，按需最小化

- 内网 IP、内网域名、VPN 地址：用 `<内网地址>` 代替，必要时只给网段
- 生产库名、库账号、表名前缀：保留结构，去掉可被直接连接的细节
- 拓扑与部署图：只描述与当前问题相关的两层

## 生产数据

- 优先造样例数据复现问题。
- 必须用真实数据时，只取与问题相关的最小行数，字段做掩码。
- 导出文件不要整份上传；给筛选条件，让对方自己查。

## 已经发出去之后

1. 在回复里不要把原值再抄一遍。
2. 提醒轮换或作废：密钥类立刻轮换；个人信息类评估是否触发内部上报流程。
3. 需要继续排查时，改用占位值复述问题。

## 不要做的事

- 不要因为一处疑似敏感信息就停止整个任务。先提示，再按用户决定继续。
- 不要自行猜测某个字符串是不是密钥后删掉用户输入；指出疑点即可。
- 不要把脱敏后的值再拼回原值，例如"掩码后四位是 1234，完整是……"。
