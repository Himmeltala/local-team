# 从输入源头控制 token

省的是发进来的内容，不是把回复压短。回复的详略与结构另有规范。

## 用位置代替内容

- 贴文件：给路径与要看的范围，如"看 `DoorRecordServiceImpl.java` 的 `listSubRegions`"。
- 贴日志：给文件路径加时间范围与关键字，不整份粘贴。
- 贴报错：给第一处异常与堆栈顶部，不贴几十行调用链。
- 贴表结构：只给涉及的表与字段，不导全库 DDL。

## 截取关键片段

- 日志只留报错前后各若干行与请求标识，其余用"中间省略"。
- 代码只留相关方法，上下文用方法签名与行号表示。
- SQL 只留出问题的条件与关联，长 `SELECT` 字段列表可省略。
- 截图优先截目标区域，不要整屏。

## 不重复粘贴

- 前文已经给出的内容，后续用"同上"或指明位置，不再贴一遍。
- 需求变更时只写改动部分，不重发整份需求。
- 同一个报错不要在多个追问里反复贴全文。

## 拆小任务

- 一次只交一件能独立验收的事；多件事分多轮。
- 大重构先给目标与边界，再按模块分批。
- 探查类任务先说清要找什么，避免"把整个项目读一遍"。

## 什么时候不要省

- 问题就出在长上下文里，省略会丢证据时，保留必要段落。
- 用户明确要求全文时，按用户要求来。
- 安全与合规要求保留完整记录时，优先合规。
