# AI 输入检查

每次收到任务、贴来的代码、日志或数据，先过三关；用户显式要求检查输入时同样走这套。检查是为了把话问清楚，不是盘问。

## 一、敏感信息

看到以下任一类，先提醒并给出脱敏建议，回复里不复述原值：

- 密钥、令牌、密码、私钥、证书内容
- 含账号密码的连接串，如数据库 URL
- 身份证号、手机号、银行卡号、证件影像路径
- 客户姓名、详细地址与能定位到个人的组合信息
- 内部 IP、内网域名、生产库名与库账号
- 生产环境导出的原始业务数据

处理方式：

- 已贴进对话的，回复里用 `<已脱敏>` 代替原值，并提醒尽快轮换密钥或收紧权限。
- 需要判断数据形态时只看位数或掩码，不取原值。
- 用户明确要求按原样处理时照办，但在回复里说明风险，不要沉默放过。

细则见 `references/sensitive-data.md`。

## 二、输入要素

任务缺以下任一项时，一次问齐，不反复追问：

- 目标：要达到什么结果
- 范围：改哪个模块、哪个环境、哪个文件
- 期望结果：改完看到什么算对
- 约束：不能动的部分、兼容要求、时间限制
- 验收标准：怎么验证完成

只是闲聊、简单查询或用户明确说"先别问"时，不套这份清单。

## 三、从源头省 token

- 能给出文件路径、函数名、行号，就不要整份文件粘贴；让助手自己按路径读取。
- 日志只留关键几行，前面加一句时间范围与筛选条件。
- 同一段上下文不要重复粘贴；已经贴过的，指明"同上"或用引用位置。
- 大任务拆成若干能独立完成的小任务，一次只交一件。
- 数据能造样例就不要贴生产数据；必须贴时按第一节脱敏。

细则见 `references/token-saving.md`。

## 边界

- 省的是用户输入给 AI 的内容，不压缩 AI 的回复。回复结构与输出侧省 token 走 `output-guard`，措辞走 `chinese-writing`。
- 发现疑似敏感信息不等于拒绝干活：提醒后由用户决定，用户要继续就继续。
- 不擅自改动用户原话，需要改写时给出改写后的版本并说明改了什么。
