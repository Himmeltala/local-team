# 抄契约：把被替换方的行为抄准

桩是否可用，取决于契约抄得准不准。抄错一个字段名、少一个错误形状，测出来的结论就是错的，而且错得很安静：桩返回 200，被测方当成成功，链路根本没验到。

## 从哪里抄

按可信度从高到低：

1. **被替换方的实现源码**。最准。真实服务在跑，它怎么解析、怎么校验、失败时返回什么字段，看源码一目了然。
2. **调用方的源码**。看它发什么、读返回体的哪个字段、怎么判成功。Java 侧常见 `code == 200`，Python 侧常见 `resp.status_code == 200`，两种判据要分别满足。
3. **抓到的真实报文**。链路曾跑通过的话，抓包或日志里的原文最省事，直接照抄形状。
4. **接口文档**。只能当线索。文档与实现不一致是常态，以源码与实抓为准。

文档与实测不一致时，以实测为准，并把差异记一句在结论里。

## 契约清单模板

每个被模拟的接口逐条填，填不出就是还没抄清：

```
接口名：
  方法：GET / POST / ...
  路径：/xxx/yyy
  尾斜杠：敏感 / 不敏感
  请求头：Content-Type、鉴权头、自定义头（如设备序列号）
  请求体字段：
    <字段名>：类型、格式（小数位、字符串还是数字）、是否可空、是否二次编码
  成功返回：HTTP 状态码 + 返回体形状（原样抄一条真实例子）
  失败返回：
    <失败类型>：HTTP 状态码 + 返回体形状 + 错误码字段名
  幂等与去重：按什么字段去重，重复请求会怎样
  副作用：对端收到后会不会回推、写库、改状态
```

成功形状与失败形状都要抄。桩只做成功分支，一遇异常路径就没得测。

## 检查点

抄的时候逐条对：

- **尾斜杠**。`/api/jobs/` 与 `/api/jobs` 在很多实现里是同一个路由，但有的框架会 301 或 404。抄的时候两边都试，桩里统一按不带尾斜杠匹配更省事。
- **字段类型与格式**。`"12.3"` 与 `12.3` 不等价，`"12.345"` 与 `"12.3"` 也不等价。小数位要照抄，很多判断是按字符串或按位数做的。
- **二次编码**。有的字段本身是 JSON 字符串（常见于"负载"这类字段），抄的时候要确认是对象还是对象序列化后的字符串。
- **枚举与编码含义**。方向、状态、类型这类字段，取值含义要从枚举类或常量里确认，别按字面猜。
- **时间与序号格式**。序号常带隐含规则，例如前缀是年份、用于分表；格式错了对端直接不认。
- **错误码字段名**。`code`、`status`、`errcode` 各家不同，取错字段会让桩的失败分支永远不生效。
- **鉴权与校验**。桩要不要校验 token、要不要校验签名，取决于被测方是否真的会带、真的会验。别替被测方把校验绕过，那等于没测。
- **对端的状态推进**。真实服务往往不是纯函数：第二次请求同一个包会被去重、会被限流、会按序号落库。桩里要显式决定要不要复刻这些行为，并在结论里写明。

## 抄完自检

- 拿一份真实的成功报文，逐字段比对桩的返回，字段名与类型必须一致。
- 拿一份真实的失败报文同做一遍。
- 每个失败分支都在桩里能触发一次，跑通再往下走。
- 契约里不确定的地方，标注出来告诉用户，不要默认。
