# 维护说明

## 来源

内容提炼自出入库一体机项目的一轮本地模拟实践，原始材料在 `~/docs/出入库一体机/2026-09-28/`：本地拉起与模拟方案、四个桩脚本、起停脚本，以及几份链路排查记录。提炼时剥掉了项目专有的端口号、接口路径与字段名，只留下可平移的方法与骨架。

模板脚本里的端口、路径、字段名一律是占位值，不代表任何项目的真实契约。`cloud_stub.py` 保留了"序号带年份前缀""负载字段二次编码"这两种常见形状，用之前必须照各自项目被替换方的源码改字段名。

被剥掉的东西不能往回加：这个插件是通用套路，不是某个项目的说明书。若某个项目专有的做法确实值得沉淀，写进那个项目的文档，不要塞进这里。

## 版本

改内容要同时提 `plugin.json` 里的 `version`，否则 `claude plugin update` 会判定"已是最新"而跳过重新复制。

## 验证记录

2026-09-28 落盘时实跑过：

- `http_stub.py`：读状态、改状态、POST 正常、POST 非法 JSON、未实现路径兜底 404，五个分支返回符合预期，日志两行齐全。
- `cloud_stub.py`：`--once` 首次下发、二次返回空。首版这里有过一个缺陷（只打日志没做闸门，第二次仍下发），已修。
- `ws_probe.py`、`sim_run.sh`：语法检查通过，未接真服务实跑。

同日插件校验发现的问题与处理：

- 模板里残留项目真值（端口 25 段、真实的订阅路径与心跳体、真实的指令字段名、真实接口路径），与"只留占位值"的口径打架。已全部换成占位值：端口改用 18080 / 18081 / 18090 与 8765，订阅路径改 `/ws`，心跳体改 `{"type":"ping"}`，指令字段改 `seq` / `deviceId` / `type` / `payload`。
- `sim_run.sh` 头部注释引用了不存在的变量名，且 `--help` 截断少打一行。已改。
- `cloud_stub.py` 的 `SEQ` 是死代码、未命中路径一律回 200 与技能正文的"兜底 404"规则相左。前者删除，后者在文件头注明本桩按代理语义工作、不适用该条规则。
- `http_stub.py` 只挂了 GET 与 POST，且故障档缺"挂起不返回"。已补 PUT 与 DELETE，并加 `--mode hang`。
- `ws_probe.py` 握手会丢掉同包到达的首帧、超时未捕获、续帧被跳过。已改为带缓冲读帧，超时按空闲处理，续帧拼完再打印。
- `sim_run.sh` 的 `status` 写死端口、就绪探测对复合命令失效。已改为从 `STUBS` 推导端口，并按端口上真正监听的进程号记录与停止。
