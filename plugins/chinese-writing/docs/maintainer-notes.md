# 维护笔记

README 只讲插件是什么、怎么装、怎么用。这份文件放维护者的东西：规则从哪来、边界在哪。

## 依据

这套规则 2026-09-23 由用户提出并逐条确认，起因是助手写中文时把语法成分当冗余砍掉：缺介词（`a + b` 代替"a 加 b"）、用符号代字（`→`、`/`、`=`）、关联词配对错乱、语序照英文摆。

两处口径由用户当场定下：

- **两套标准**：落盘产出（注释、提交信息、文档）规范优先，介词、量词、关联词写全；对话回复精简优先，允许电报体、允许省介词。禁符号代字与中英混排空格两条例外，对话回复也照办。
- **中英混排加空格**：中文与英文、数字之间留一个半角空格，例如 `你好 nihao`、`123 你好`。

## 调整约定

- 会话常驻提醒的正文在 `hooks/session-rules.txt`，保持简短——每次会话都会占用上下文。当前 175 字符。上限是 10000 字符，超了会被换成文件路径加预览，等于失效。
- 符号规则以本插件为准，`comment-style` 只管注释特有的部分（字符串字面量与注解值是数据，不算符号代字）。两处不要各写一份。
- 规则细则写在 `skills/chinese-writing/references/` 下：`symbols-and-grammar.md` 管写，`reading-chinese.md` 管读。SKILL.md 只留八条主干与反例速查。
- 新增符号对照时把"想表达的意思"写清楚：同一个 `+` 可能是"加"，也可能是"与"；同一个 `/` 可能是"或"，也可能是"每"。判断标准是这句话说给人听还是给程序读。
