# 裁剪规则：删什么、留什么

## 范围

**整文件。** 本次编辑碰到哪个文件，那个文件里的乱注释一并清干净——不再限定在改动的函数 / 方法 / 模板块内。

**没编辑过的文件一律不碰。** 触发条件是"我正在改这个文件"，不是"这个模块看着乱"。整目录的存量清理归 `comment-trimmer` 子代理。

理由是文件级一致性。清一半的文件比不清更麻烦：下一个改它的人要重新判断哪些注释该留，判断标准还会漂；旧写法与新写法在同一个文件里并存，读者分不清哪个是本团队现行口径。一次清完，文件从此是干净的基线。

代价是 diff 变大——审阅的人得分清哪处是本次需求、哪处是顺带整理。这个代价用提交信息对冲：只要清理动到了本次改动之外的注释，就在那一行提交信息里体现（例如 `refactor: 整理统计接口并顺带清理注释`）。提交信息只有一行，不要为说明清理另起一行。

极端情况：几千行的存量文件、清理量远超本次改动。仍然整文件清完，但要先在回复里说明这次改动会带出多大范围的注释整理，让用户知道 diff 里哪些是与需求无关的。

## 删除对象

| 类型 | 例子 | 本仓库实测 |
|---|---|---|
| 装饰横幅与分割线 | `// ========== 用户模块 ==========`、`/* ***** */`、`<!-- ===== -->` | 127 处，真实存在 |
| 注释掉的死代码 | `// private String oldField;`、`//  if (CollUtil.isEmpty(x)) {` | 106 处，集中在 `HardwareViewController` |
| emoji 与无义装饰 | `// TODO 🚀`、`// ★ 重要`、`// ➜ 下一步` | 未检出 |
| 翻译式注释 | 方法 `setName()` 上写 `// 设置名称` | 需人工判断 |
| 复述代码 | `// 循环遍历`、`// 判空`、`// 返回结果` | 需人工判断 |
| 变更履历 | `// modify by lisi`、`// 2023-05-11 张三 新增` | 后端 0 处 |
| 流程标语 | `// 第一步：校验`、`// 开始处理` | 需人工判断 |
| 简单方法上的 Javadoc | 三行 Javadoc 说明一个 `getId()` | 需人工判断 |
| 无信息量的占位 | `/** 构造方法 */`、`// 无` | 需人工判断 |

「本仓库实测」列是 2026-09-23 对一个存量后端项目（990 个 Java 文件规模）跑正则得到的数量，只用来判断**哪些模式值得先扫**，不代表新项目。新项目规模不同，数字会变，先扫这两类能命中的，再靠人工判断其余的——不要指望正则捞出全部。日期开头的变更履历注释（`// 20xx-xx-xx`）实测 0 处，不要为一类不存在的模式写复杂正则。

**横幅注释先剥装饰，别整行删。** 后端现有 127 行这种写法，其中多数横幅本身带着下一段代码在做什么：

```java
// ===================== 批量一次性查全时段告警，不再循环单条count =====================
```

正确做法是只去掉 `=====` 装饰，留下句子：

```java
// 批量一次性查全时段告警，不再循环单条 count
```

只有文字本身也是空话时才整行删，例如 `// ============ 工具方法 ============`。

## 保留对象

| 类型 | 例子 |
|---|---|
| 业务规则与口径 | `// 区县级账号无下级区域时回退统计本级` |
| 补偿性处理与坑 | `// 虚谷库不支持按聚合表达式排序，须用 SELECT 别名`（团队主力数据库的已知限制，写清库名与原因） |
| 单位 / 精度 / 量纲 | `// 金额单位：万元` |
| 数据来源与更新时机 | `// 由审核服务在通过/驳回时写入` |
| 功能性指令 | `//noinspection`、`eslint-disable-next-line`、`@SuppressWarnings`、`@SuppressFBWarnings` |
| 待办标记 | `TODO`、`FIXME`（去掉装饰，写清做什么） |
| 类级元信息 | 许可证头、`@author`、`@date`、Java 类 Javadoc 的 `<b>功能：</b>` 模板 |
| 前端文件头块 | `.vue` / `.js` 顶部的 `@Author` / `@FilePath` 等六字段块，eslint 强制 |
| 接口契约说明 | `@ApiModelProperty`、`@ApiOperation`、`@Api` |
| 箭头符号 | 注释里禁 `→` 与箭头区 `←` 到 `⇿`；映射、换算、流转一律写成文字 |

## 符号：不写符号，写成文字

注释里的箭头一律删，承义也不例外。映射、换算、流转原来靠箭头省字，改写成文字，意思一点不丢。

存量后端有 32 个文件的注释里用了 `→`，都属违规，改到时顺手转成文字。

```java
// 改前（违规）
// 同步枢纽服务一次性拉取全部区域，用于弹药 regionId → orgCode 匹配
// $4=available (KB) → GB
// 仅为真正从在线→离线的设备生成告警记录，避免重复生成

// 改后
// 同步枢纽服务一次性拉取全部区域，用于弹药 regionId 映射到 orgCode 的匹配
// $4=available，单位由 KB 换算成 GB
// 仅为真正由在线转为离线的设备生成告警记录，避免重复生成
```

```java
// 装饰符号，直接删
// ★ 重要：这条 SQL 不能加索引
// ➜ 下一步优化
// ========== 用户模块 ==========
```

**只在注释里判断。** 箭头也出现在字符串字面量和注解值里，那里是数据不是样式：

```java
remark = online == 1 ? "离线→在线" : "在线→离线";          // 字符串，改了就是改行为
@ApiOperation(value = "区域在线统计", notes = "…可下转（市→县、县→本级）")   // 注解值，是接口文档
```

这两处**一个字都不许动**——本节示例里出现的这些字符是数据，不代表允许在注释里写箭头。裁剪只碰 `//`、`/* */`、`<!-- -->` 里的文本。

前端更省事：`local/illegal-annotation` 早把箭头判为违规，跑 `npm run lint` 让它自己修。

## 判断标准

只有一条：**删掉这行，后来人会误改或者看不懂吗？**

- 会，留。
- 不会，只是"看着像注释"，删。
- 拿不准，留。删错了要重建，留多了顶多占一行。清理的收益不值得冒丢信息的风险。

这一句同时是 `comment-trimmer` 子代理的判据，别在别处再写一份。

## mapper XML 另作处理

`src/main/resources/mapper/*.xml` 里的 `--` 注释不按本文件的默认尺度裁——那里的编号前缀与引擎坑说明都承载信息。单看 `xml-sql-conventions.md`。

## 绝对不做

- 不改代码逻辑。裁剪只碰注释与空行。
- 不动字符串字面量、注解值、SQL 字符串里的任何字符——那里的 `→`、`★` 是数据不是样式。
- 注释里遇到箭头不整行删句子，改写成文字；拿不准就保留并列入报告。
- 不动本次没有编辑的文件。顺手裁剪的入口是自己正在改的文件，不是"路过觉得乱"。
- 不重写存量类头。`@title` / `@description` / `@date` 那套历史写法保持原样。
- 不把字段上的 `@ApiModelProperty` 当注释删掉，也不把它改成 Javadoc。它是接口文档，不是装饰。
- 不删 eslint 指令、`@SuppressWarnings`、`//noinspection`。
- 不删 `TODO` / `FIXME`，只去装饰。
- 不动 `node_modules/`、`target/`、`dist/`、`build/` 下的任何东西。
- 不做全文件重排、不统一缩进、不调整空行风格。那不是本次任务。

## 裁剪后自检

1. 该文件里是否还留着本次该清的乱注释？本次编辑没碰的文件，是否一处未动？
2. 功能性指令是否完好？`grep -n "eslint-disable\|noinspection\|SuppressWarnings"` 对比裁剪前的数量。
3. 有无把该留的业务说明一起删掉？重点回看含"因为 / 由于 / 注意 / 兼容 / 口径"字样的行。
4. 编译或 lint 是否仍然通过？Java 改动至少确认无语法错误；前端跑 `npm run lint`。
