# 提交信息格式细则

## 唯一规则：只有一行，且要短

提交信息就是一行：

```
<type>: <中文描述>
```

- 没有第二行。
- 没有正文段。
- 没有 `-` 或编号列表。
- 没有空行。
- 前缀后没有范围括号。
- 整行尽量控制在 50 字以内。

`svn commit -m` 里传一个单行字符串即可。换行符不该出现在提交信息里。

细节写不进去时，写进代码注释，或者当面说。提交信息是索引，用来检索"哪次改了什么"，不是变更文档。

## 前缀含义

| 前缀 | 用于 |
|---|---|
| `feat` | 新增功能、新增接口、新增字段 |
| `fix` | 修复缺陷、修正错误数据、补齐漏返回字段 |
| `refactor` | 重构，行为不变 |
| `perf` | 性能优化 |
| `docs` | 文档、注释、说明 |
| `style` | 格式调整，不影响行为 |
| `test` | 测试相关 |
| `chore` | 构建、依赖、配置杂项 |
| `build` | 构建脚本、打包配置 |
| `ci` | 持续集成配置 |
| `revert` | 回退先前提交 |

范围（括号部分）不写。Conventional Commits 允许 `fix(doorRecord):` 这种带范围前缀的写法，本团队不用：提交信息统一是 `<type>: <中文描述>`，前缀后面直接紧跟半角冒号和空格。要指明模块或接口，把名字写进中文描述里——`fix: 门禁记录统计接口补齐无数据的区域与操作类型`，而不是 `fix(doorRecord): 统计接口补齐...`。中文描述本身就带模块信息，再套一层括号只会让同一件事有两种写法。

## 单行好例

```
feat: 新增资产分布分区域设备统计接口（含本级及下级），金额单位统一为万元
```

```
fix: 门禁记录统计接口补齐无数据的区域与操作类型
```

```
feat: 作业信息统计表新增同步批量接收与水位接口
```

写完读一遍：别人只看这一行，能知道改了什么吗？能，就够了。

## 反例

| 反例 | 问题 |
|---|---|
| `feat(api): 新增门禁记录统计接口` | 前缀带了范围括号，本团队不用；写成 `feat: 新增门禁记录统计接口` |
| `feat： 修改运行数据统计逻辑` | 全角冒号；描述空泛 |
| `告警查询` | 漏前缀；看不出改动内容 |
| `fix bug` | 全英文、无上下文、无法检索 |
| 任何带第二行的提交信息 | 违反单行规则 |

最后一类要特别注意：**历史提交里有大量带正文的写法**——"原逻辑是…现改为…"、编号列表、空行分段。那是过去的做法，现在不允许。写新提交时不要照着 `svn log` 里的旧样式模仿，只学前缀和"半角冒号 + 中文描述"这两点。

如果某次改动确实复杂到一行说不清，说明这次提交本身可能包含多件事。先考虑拆成多次提交，每次一行。

## 提交前最后一眼

- 只有一行，没有换行符
- 冒号是半角 `: `，不是 `：`
- 前缀存在且正确
- 前缀后面没有 `(...)` 范围括号
- 这一行能读懂改了什么
- 一行不超过 50 字左右
